# Source classification policy - proposed

## Rule

Classifying a source identifies how it may be used. It does not independently make a source normative.

| Class | Permitted use | Current examples |
| --- | --- | --- |
| Authoritative AAVLD requirement | Primary traceability target; may support a statement that restates an AAVLD requirement. | AAVLD Requirements for an Accredited Veterinary Medical Diagnostic Laboratory, 1137 Version 1. |
| Historical baseline | Compare prior scope and wording; do not treat as current authority. | AAVLD Informatics Subcommittee Accreditation IT Guidance, October 2007. |
| Committee direction | Records agreed intent and unresolved work; does not substitute for an approved guidance statement. | 2025 IT Committee meeting notes. |
| Related reference | Supports interpretation or context, clearly attributed. | ISO/IEC 17025, if selected by the committee. |
| Informative technical reference | Supplies optional implementation patterns; never becomes mandatory merely by citation. | NIST CSF, GAMP concepts, if selected. |
| Development-process reference | Governs drafting/review practice only; never cited as a laboratory IT control. | ISO/IEC Directives, RFC 8874, OASIS lifecycle. |

## Drafting test

Every substantive sentence must be marked internally as one of: `AAVLD-derived requirement`, `guidance recommendation`, or `informative example`. A sentence that cannot meet one of these classes is an open issue.

## Committee decisions required

- Confirm whether ISO/IEC 17025 is a related reference, an informative reference, or excluded from the published guidance.
- Approve the terms used for requirement, recommendation, and example.
