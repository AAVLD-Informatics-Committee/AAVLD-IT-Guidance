# Requirements-to-guidance traceability - working matrix

This is a prework matrix, not a statement of final committee interpretation. `Decision` marks an item that needs committee confirmation before it becomes guidance text.

| AAVLD clause | IT topic | Proposed guidance outcome | Status |
| --- | --- | --- | --- |
| 4.1.4.3 | Confidential electronic storage and transmission | Laboratories identify and protect confidential client information in storage and transmission. | Candidate section: data protection. |
| 4.3 | Document control | Software, configuration, and procedures affecting test results are identified, controlled, and changed under an approved process. | Decision: software as document/equipment treatment. |
| 4.10.1.1-4 | Records management, retrieval, security, backup | Technical and quality records are identifiable, retrievable, retained, backed up, and protected from unauthorized access or amendment. | Candidate section: data lifecycle. |
| 4.10.2.3-4 | Computer-collected data and LIMS records | Original data and LIMS technical records are protected from unauthorized change, tampering, and loss. | Candidate section: integrity and auditability. |
| 5.4.2.2 | Verification before introduction or method change | Where an IT change affects a test method's use, evidence is retained that the change is fit for intended use. | Decision: relationship between method and system verification. |
| 5.4.4.1-2 | Secure, retrievable, approved data; transfer checks | Test data and validation data are secure, retrievable, approved for use, and subject to appropriate checks. | Candidate section: data lifecycle. |
| 5.4.4.3.1 | User-modified/developed software | User-modified or developed software is documented and suitably validated or checked; changes are recreatable and auditable. | Candidate section: validation and change control. |
| 5.4.4.3.2 | LIMS and interface validation | LIMS functionality and interfaces are validated before introduction; additions or deletions are authorized, documented, and validated before implementation. | Candidate section: LIMS and interfaces. |
| 5.4.4.3.3-4 | Data security, integrity, retrievability, operating environment | Procedures protect data entry, storage, transmission, processing, and the operating conditions needed for integrity. | Candidate sections: security; operations. |
| 5.4.4.4-6 | LIMS access, failures, external providers | LIMS access, tampering/loss safeguards, nonconforming-work handling, and external-provider accountability are addressed. | Decision: provider assurance evidence. |
| 5.5.2, 5.5.11 | Equipment software and safeguards | Equipment software affecting diagnostic activities meets relevant specifications and is safeguarded against invalidating adjustment. | Candidate section: system inventory and lifecycle. |
