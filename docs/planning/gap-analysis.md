# Gap analysis - 2007 baseline to current update

## Observed continuity

The 2007 guidance already provides useful assessor-oriented questions on network controls, LIMS access, auditability, validation/qualification, configuration and data changes, backups, and recovery. It explicitly avoids prescribing a particular computer-system setup.

## Proposed update gaps

| Topic | 2007 baseline | Current update need | Disposition proposal |
| --- | --- | --- | --- |
| Purpose and audience | Assessor question framework. | Clarify minimum IT needs supporting accreditation and intended users. | Committee decision. |
| Scope | Three sections: network security, data integrity, disaster planning. | Cover the system/data lifecycle while retaining a risk-based, non-vendor-specific approach. | Expand architecture. |
| Source authority | Older OIE-era context. | Direct traceability to current AAVLD clauses. | Add matrix and source register. |
| System inventory | LIMS, support systems, and instrument computers appear in questions. | Define a repeatable inventory and criticality approach. | Add guidance topic/example. |
| Validation language | Installation, operational, and performance qualification. | Clarify validation versus verification, intended use, interfaces, and changed functionality. | Committee decision plus modernized section. |
| Cloud/external providers | Outside interfaces mentioned. | Address AAVLD 5.4.4.6 provider accountability without prescribing contracting terms. | Add provider topic. |
| Data integrity/audit trail | Data-change tracking asked. | Make integrity, authorization, retrievability, and auditability explicit across the data lifecycle. | Expand and map to 4.10/5.4.4. |
| Continuity | Disaster planning, backups, recovery, personnel. | Include recovery testing and data validation after restoration. | Retain and modernize. |
| Security detail | Product-era questions about antivirus/antispyware and password age. | Express outcomes, not dated product controls. | Replace with risk-based control outcomes. |

## Committee decisions to surface

1. Is the product primarily assessor guidance, laboratory implementation guidance, or both?
2. What minimum evidence should be described for validation, verification, and change control?
3. How should the guidance distinguish LIMS, interfaces, instrument software, spreadsheets, and general infrastructure?
