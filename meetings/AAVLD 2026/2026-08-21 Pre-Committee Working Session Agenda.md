# AAVLD IT Guidance - Pre-Committee Working Session

**Date/time:** Friday, August 21, 2026, 3:00-4:00 PM Eastern
**Purpose:** Prepare a coherent working draft and a decision-ready package for
the main committee meeting.

This session is for drafting, review, task assignment, and recommendation
development. It does not replace formal committee decisions.

## Preparation

- Review the [AAVLD IT Guidance Modernization project](https://github.com/orgs/AAVLD-Informatics-Committee/projects/2).
- Review the [working-draft issue](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/8) and the [potential coverage inventory](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/16).
- Bring missing coverage, suggested edits, and questions requiring the full
  committee.

## Agenda

1. **0:00-0:05 - Opening and outputs**
   - Confirm this group prepares recommendations and a working draft for the
     main committee.
   - Assign a facilitator, recorder, and task owner(s).

2. **0:05-0:15 - Review the working foundation**
   - Review the [update initiative](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/1), [source classification](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/3), [traceability](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/5), [architecture](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/7), and [working draft](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/8).
   - Confirm the guardrails: laboratory audience; no new accreditation
     obligations; vendor-neutral examples; external frameworks informative unless
     explicitly adopted.

3. **0:15-0:30 - Triage potential coverage**
   - Review [issue #16](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/16).
   - Identify likely **Core**, **Conditional**, and **Out-of-scope** topics.
   - Capture missing veterinary diagnostic workflows, systems, and interfaces.
   - Do not attempt final committee approval in this session.

4. **0:30-0:43 - Working-draft review and task assignment**
   - Review the current section structure and identify needed edits.
   - Assign volunteers to propose text, trace sources, prepare optional examples,
     or identify gaps.
   - Capture each task in GitHub as an issue or an issue comment, with an owner
     and target date.

5. **0:43-0:53 - Prepare main-committee decisions**
   - State the recommended resolution or question for each open decision:
     - [#13 Stakeholder/public review](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/13)
     - [#14 Non-obligation scope](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/14)
     - [#15 Validation, verification, and change-control evidence](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/15)
     - [#16 Coverage scope](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/16)
     - [#17 Reporting standards coverage](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/17)
     - [#18 ISO/IEC 17025 relationship](https://github.com/AAVLD-Informatics-Committee/AAVLD-IT-Guidance/issues/18)

6. **0:53-1:00 - Closeout**
   - Confirm decisions to advance, unresolved questions, task owners, and due
     dates.
   - Confirm proposed main-committee agenda topics and recommended speakers.

## Expected outputs

- Prioritized draft edits and prework tasks, each with an owner and target date.
- Recommended Core/Conditional/Out-of-scope coverage dispositions.
- A concise decision packet for the main committee.
- Candidate main-meeting topics and speakers.

## Recording rules

- The current AAVLD Requirements remain the authoritative source for
  accreditation obligations.
- The guidance helps laboratories implement existing requirements; it does not
  create new ones.
- Record tasks, review comments, and decision requests in GitHub issues; use the
  project to track status.
